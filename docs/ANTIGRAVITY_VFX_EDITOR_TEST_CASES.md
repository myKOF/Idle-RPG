# Antigravity 測試用例：VFX 編輯器的檢視、群組數值與存檔快捷鍵

## Feature

2026-09-09 的 VFX Editor 優化，共六項：

1. 預覽區的淺色座標格線（1 大格 = 6 米，與遊戲同比例）
2. 滾輪縮放（中鍵回 100%）
3. 工具列的 Loop 改成「預覽循環」，`preset.loop` 移進 Inspector 的「Preset」區塊
4. 群組 Inspector 顯示並可輸入尺寸與變形
5. Ctrl+S 存檔
6. 下拉旁邊的「⧉ 複製」按鈕（把 preset 名稱複製到剪貼簿）

對應 commit：`531e638`（編輯器）與 `ea390b1`（單一根群組規範）。

## Test Goal

這次 QA 要證明三件事，其餘都是附帶：

- **格線量得準。** 它是量尺，算錯不會報錯也不會看起來壞掉，只會安靜地量錯，
  而「這個特效比判定範圍大一圈」正是靠它判斷的。
- **預覽循環沒有污染 `preset.loop`。** 那是會出貨的資料。改到它不會有任何提示，
  要到遊戲裡才發現爆點變成永遠不結束、或光環只閃一下就沒了。
- **Ctrl+S 存的是畫面上看到的內容。** 數值欄位是失焦才寫回 preset 的，
  沒處理好就會存到打字之前的舊值，而且完全沒有跡象。

其餘案例是迴歸：縮放不得弄壞既有的 Gizmo 拖曳，群組打數字不得與拖曳結果不一致。

## Preconditions

### 分支

這五項在 `ai/claude`，Antigravity 的 worktree 沒有。**先合併再測**，
不要直接開 claude 那份工作副本——本次 QA 會寫檔（Ctrl+S、群組變形），
而 `VFX_AGENT_WORKFLOW §3.3` 規定 Antigravity 預設不直接修改 Claude worktree。

```bash
git -C D:/MyGame/Idle-RPG/antigravity merge --no-ff ai/claude
```

### 啟動編輯器

在 **`D:\MyGame\Idle-RPG\antigravity`** 執行 `啟動VFX編輯器.bat`。

啟動後**務必確認連到的是自己那份**。五份工作副本共用 28361~28370 這段埠，
伺服器遇到占用會自己往下換，但瀏覽器可能停在別人的編輯器上：

```bash
curl -s http://127.0.0.1:<實際開啟的埠>/__whoami
```

必須回 `idle-rpg-vfx-editor D:\MyGame\Idle-RPG\antigravity`。
回別的目錄就是連錯了，這次 QA 的結果全部作廢。

### 其他

- 開著 DevTools Console，全程不得出現任何錯誤。
- 測試用 preset：`beam-light`（3 層，`loop: false`，純 sprite）與
  `lightning-orb-field`（5 層，`loop: true`，含粒子層）。
  **開始前先確認這兩份的 `loop` 還是這個值**——preset 是使用者隨時在改的資料，
  用 `grep '"loop"' vfx/presets/<id>.json` 核對；對不上就換一份符合的，
  並在報告裡註明換成了哪一份。
  用網址切換：`.../tools/vfx/editor/index.html?preset=<id>`
- **會寫檔的案例是 AG-VFXED-006、007。** 做完用
  `git -C D:/MyGame/Idle-RPG/antigravity status` 確認改到了哪些檔，
  再用 `git checkout -- <檔案>` 還原。回報時附上還原前的 `git status`。
- 第一次開之前先清掉這三個 localStorage 鍵，才測得到預設值：
  `vfx-editor.grid`、`vfx-editor.previewLoop`、`vfx-editor.background`

## Test Steps / Expected Result

### AG-VFXED-001：格線的比例尺（最重要）

操作：

1. 開 `beam-light`，確認右上顯示「縮放 100%」、旁邊寫「1 大格 = 6 米（60px）」。
2. 在 Layers 展開群組、選第一個圖層，Inspector 的 position 填 x = `60`、y = `0`，按 Enter。
3. 觀察預覽上那個橘色十字（pivot）落在哪裡。
4. 把 position 改成 x = `180`、y = `0`。
5. 把 position 改回 x = `0`、y = `0`。
6. 在 Layers 選群組列 `beam-light`，讀 Inspector 的「寬（px）」與底下那行米數。

預期：

- 步驟 3：橘色十字**剛好**落在垂直軸線右邊第一條大格線上（不是附近、不是第二條）。
- 步驟 4：落在右邊第三條大格線上。
- 步驟 6：寬 ÷ 60 = 這個群組橫跨的大格數，與底下那行「N × M 米」對得上
  （米數 = px ÷ 10）。用眼睛數綠色虛線框橫跨幾個大格來核對。
- 大格之間還有較淡的小格；每個大格內剛好 6 個小格（1 小格 = 1 米）。

**這一條不過就不必往下測**，格線的比例尺錯了其他都沒意義。

### AG-VFXED-002：格線在每一種背景上都看得見

操作：

1. 把背景色列的每一張色票都點過一輪，包含最右邊的棋盤格。
2. 每一張都看格線是否還在、會不會反而搶戲。
3. 用「自訂」取色器拉一遍由全黑到全白，觀察線色何時翻轉。

預期：

- 深色背景（預設深色、純黑、夜空藍、洞窟土色、森林綠、棋盤格）：格線是**淺色**的。
- 淺色背景（雪地灰藍、淺色）：格線自動變成**暗色**——白線在那上面等於沒畫。
- 任何一張背景上，格線都是「淡淡一層」，不得亮到會被誤認為特效的一部分。
- 拉取色器時線色在中間亮度附近翻轉一次，不得閃爍或殘留兩種顏色同時存在。

### AG-VFXED-003：滾輪縮放與中鍵歸零

操作：

1. 滑鼠移到預覽區，滾輪往上滾數格，再往下滾數格。
2. 一路往上滾到底，記下右上的百分比。
3. 一路往下滾到底，記下百分比。
4. 在預覽區按一下**滑鼠中鍵**。
5. 點右上「縮放 xxx%」那個按鈕。
6. 滾輪縮放的**同時**注意整個頁面有沒有跟著上下捲動（先把瀏覽器視窗縮矮，讓頁面出現捲軸）。

預期：

- 往上放大、往下縮小；百分比與「1 大格 = 6 米（N px）」同步更新。
- 上限 800%、下限 25%，到底之後繼續滾不會再變、也不會出現負數或 NaN。
- 步驟 4、5 都回到 100%。
- **步驟 6：整頁不得捲動。** 這是明確的失敗條件。
- 縮放中心永遠是預覽正中央（特效原點），不是滑鼠位置——這是設計如此，不是 bug。
- 縮到 25% 時小格會消失、只剩大格；放大時小格回來。這是刻意的（線太密會糊成灰霧）。

### AG-VFXED-004：縮放之後 Gizmo 還是準的（迴歸）

操作：

1. 縮放到 400%，選一個 sprite 圖層。
2. 拖曳白框內部移動它，觀察框與素材是否一起走、滑鼠與框有沒有偏移。
3. 拖曳四角把手縮放、拖上方圓點旋轉。
4. 縮放到 25%，重複步驟 2~3。
5. 在 400% 與 25% 各按一次 Esc 取消拖曳到一半的操作。
6. 縮放到 400%，點預覽上另一個圖層的位置，看是否選得到它。

預期：

- 任何倍率下，框都貼著素材，拖曳時框跟著滑鼠**同步**移動，不會落後或跑更快。
- 把手與 pivot 十字在螢幕上**大小不變**（不隨縮放變大變小），但位置正確。
- 命中判定準確：點到哪一層就選到哪一層，不會偏一整格。
- Esc 能取消，且 Ctrl+Z 一次就回到拖曳前。

### AG-VFXED-005：預覽循環與 `preset.loop` 是兩件事（最重要）

操作：

1. 開 `beam-light`（`loop: false`）。看工具列的「預覽循環」是否**預設勾選**。
2. 觀察預覽：特效播完之後會不會自己再來一次。
3. 看 Inspector 最上方的「Preset」區塊，`loop` 應該是**沒勾**的。
4. 確認右上角**沒有**出現未存檔標記（`*` 或「未存檔」）——光是打開不該讓它變髒。
5. 取消勾選「預覽循環」，按 ⟲ Restart，觀察播完之後是否停住不再重播。
6. 重新勾選「預覽循環」。
7. 開 `lightning-orb-field`（`loop: true`）。Inspector 的 `loop` 應該是**勾選**的。
8. 在 Inspector 把 `loop` 取消勾選，確認右上出現未存檔標記；按 Ctrl+Z 復原，標記消失。
9. 重新整理頁面，確認「預覽循環」記得步驟 5、6 的選擇（它存在 localStorage）。

預期：

- 步驟 1：預設勾選。
- 步驟 3、7：Inspector 的 `loop` **忠實反映該 preset 的資料**——這是這次修掉的 bug，
  以前不論開哪一份都是空的。
- 步驟 4：**打開 preset 不得讓它變成未存檔。** 這是明確的失敗條件。
- 步驟 8：只有 Inspector 那格會讓 preset 變髒；工具列那格永遠不會。
- 切換「預覽循環」不進 Undo 歷史（按 Ctrl+Z 不會把它切回來）。

### AG-VFXED-006：群組 Inspector 的數值與拖曳一致

**這一條會改到 preset，做完要還原。**

操作：

1. 開 `lightning-orb-field`（含粒子層），在 Layers 點群組列選取整個群組。
2. 記下 Inspector 的「中心 x/y」「寬（px）」「高（px）」與底下那行米數。
3. 在「縮放 ×」填 `2`，按 Enter。記下新的寬高。
4. Ctrl+Z 復原，確認寬高回到步驟 2 的值。
5. 這次改用**拖曳右下角把手**，把群組拉到大約兩倍大，記下寬高。
6. 比較步驟 3 與步驟 5 的畫面：粒子的大小、噴發範圍、飛行距離是否一樣跟著放大。
7. Ctrl+Z 復原。
8. 在「旋轉 Δ°」填 `90`，按 Enter，觀察整組是否繞中心轉了 90 度、粒子的噴發方向是否跟著轉。
9. 觀察「縮放 ×」與「旋轉 Δ°」在套用後是否歸回 `1` 與 `0`。
10. 在「寬（px）」直接填一個明確的數字（例如 `600`），按 Enter，確認框真的變成那個寬度。
11. 全部 Ctrl+Z 復原到乾淨，確認右上的未存檔標記消失。

預期：

- 步驟 3 的寬高剛好是步驟 2 的兩倍；底下的米數同步。
- **步驟 6 是重點**：打數字與拖把手的結果要一致，特別是粒子——它不吃 `layer.scale`，
  縮放動到的是 `startScale`／`speed`／`spawn`／`gravity`。只有其中一項沒跟著變就是失敗。
- 步驟 8：旋轉之後粒子往新的方向噴，不是還往原本的方向。
- 步驟 9：兩格歸零。它們是「再套用多少」，不是絕對值——群組沒有絕對的縮放倍率可顯示。
- 「中心 x/y」「寬」「高」是絕對值，改了之後顯示的就是新的絕對值。
- 每一次數值變更都是**一步** Undo，不是每打一個字一步。

### AG-VFXED-007：Ctrl+S（最重要）

**這一條會寫檔，做完要還原。**

操作：

1. 開 `beam-light`，選一個圖層。
2. 在 `alpha` 欄位打 `0.42`，**不要按 Enter、不要點別的地方**，直接按 Ctrl+S。
3. 觀察：瀏覽器有沒有跳出「另存新檔」對話框。
4. 觀察右上的存檔狀態文字。
5. 用文字編輯器直接打開 `vfx/presets/beam-light.json`，看 `alpha` 存的是多少。
6. 在瀏覽器分頁的其他地方（例如 Asset Browser 的搜尋框）按 Ctrl+S，確認一樣不會跳對話框。
7. 把 `preset.id` 改成一個與檔名不同的值，再按 Ctrl+S。
8. 還原：`git checkout -- vfx/presets/beam-light.json`

預期：

- 步驟 3、6：**瀏覽器的「另存新檔」對話框絕對不能出現。** 這是明確的失敗條件。
- 步驟 4：顯示「已存檔 · N bytes」（綠色）。
- 步驟 5：檔案裡是 **`0.42`**，不是舊值。這是這一條的核心——沒處理好的話存進去的是
  打字之前的內容，而畫面上顯示的是新值，兩邊對不起來且沒有任何提示。
- 步驟 7：擋下存檔並說明原因（id 與載入來源不一致），不得寫到另一個檔案上。
- 按鈕上的提示文字要寫著 Ctrl+S（滑鼠停在「儲存到 repo」上）。

### AG-VFXED-008：檢視偏好的持久化與 Undo 隔離

操作：

1. 取消勾選背景色列右邊的「格線」，確認格線消失、旁邊那行米數說明也一起消失。
2. 換一個背景色、縮放到 200%。
3. 按 Ctrl+Z 好幾次。
4. 重新整理頁面。

預期：

- 步驟 3：Ctrl+Z **不會**把格線切回來、不會換回原本的背景、不會回到 100%。
  這些是「怎麼看」，不是編輯內容。
- 步驟 4：格線開關與背景色記得住（存 localStorage）；**縮放回到 100%**（刻意不記——
  隔天打開看到 320% 會以為素材被誰改大了）。
- 整個過程右上都不該出現未存檔標記。

### AG-VFXED-010：複製 Preset 名稱

操作：

1. 開任何一份 preset，點下拉右邊的「⧉ 複製」。
2. 觀察按鈕的文字變化。
3. 到記事本或網址列按 Ctrl+V。
4. 用下拉切換到另一份 preset，再按一次「⧉ 複製」、再貼一次。
5. 把 Inspector 裡的 `id` 欄位改成別的名字（**不要存檔**），再按「⧉ 複製」、再貼一次。

預期：

- 步驟 2：文字暫時變成「✓ 已複製」，約一秒半後變回「⧉ 複製」；
  整條工具列不得因為文字變長變短而左右抽動。
- 步驟 3、4：貼出來的就是下拉上顯示的那個 preset id，沒有多餘的空白或引號。
- 步驟 5：貼出來的仍然是**下拉上顯示的**那個 id（實際載入的來源），
  不是剛剛改的那個還沒落檔的名字。
- 如果顯示「✕ 失敗」（紅字），請回報你的瀏覽器與是否為 `http://127.0.0.1`——
  這條路在某些內嵌瀏覽器裡會整個失效，需要知道是哪一種環境。

### AG-VFXED-009：既有功能迴歸

操作：把下列既有流程各跑一次，確認沒有被這次的改動弄壞：

1. Asset Browser 搜尋、篩選、雙擊套用素材。
2. 素材選擇器（Picker）開關、Esc 關閉。
3. 新增／刪除圖層、組成群組／解散、拖曳排序。
4. Over-Life 曲線編輯（拖控制點、切換分區／對照模式）。
5. 漸層編輯器。
6. 播放／暫停／Restart。
7. 「下載複本」、「載入 Preset」。
8. Spine 參考面板開關。
9. Ctrl+Z / Ctrl+Y、Ctrl+C / Ctrl+V。
10. Delete 刪圖層（焦點在文字欄位時 Delete 應該是刪字元，不是刪圖層）。

預期：全部維持原本行為，Console 無錯誤。

## Edge Cases

必須額外測到的邊界情況：

1. **把左右側欄拉窄／拉寬，或改變瀏覽器視窗大小**——格線要跟著重畫並保持與原點對齊，
   不得出現「畫布變大了但右半邊沒有格線」或格線被裁掉。
2. **縮放到 800% 之後改變視窗大小**，再縮回 100%，確認格線與 Gizmo 都還對齊。
3. **在拖曳圖層的過程中滾輪縮放**（按住左鍵不放、同時滾輪）——不得讓圖層跳走或框錯位。
4. **快速連續滾動**（用力撥滾輪、或用觸控板兩指快速滑）——不得一口氣跳到上下限，
   也不得出現百分比亂跳。
5. **群組只剩一層時**選取它，Inspector 的寬高應該仍算得出來。
6. **在群組欄位輸入非法值**：寬填 `0`、`-100`、`abc`，縮放填 `0`、負數。
   應該不套用、不讓框消失、不產生 NaN，Console 無錯誤。
7. **preset 參數改到不合法時**（例如 scale 填成空的），驗證區要報錯；此時按 Ctrl+S
   應被擋下並說明原因，不得寫出壞檔。
8. **同時開兩個編輯器分頁**改同一份 preset，各自按 Ctrl+S——確認後存的覆蓋前存的，
   而不是寫出半份檔案。（這是既有行為，只是要確認 Ctrl+S 沒有繞過既有的存檔守門。）

## Visual / UX checks

主觀但必須回報：

1. 格線的濃度會不會干擾判讀特效？特別是在加法混合的亮素材上，以及棋盤格背景上。
2. 軸線（穿過原點的那兩條）是否明顯到能一眼找到原點，又不至於被誤認為特效的一部分？
3. 25%～800% 全程滾一遍，縮放的**手感**是否線性？有沒有某一段特別鈍或特別敏感？
4. 「格線」勾選框、「縮放 xxx%」按鈕、「1 大格 = 6 米」說明文字擠在背景色列右邊，
   視窗變窄時會不會換行成很醜的樣子、或把背景色票擠掉？
5. 「預覽循環」與 Inspector 的 `loop` 是兩個不同的東西——第一次看到的人分得出來嗎？
   如果分不出來，請具體說明是哪裡讓人混淆（文字？位置？）。
6. 群組 Inspector 的「縮放 ×」套用後歸 1，這個行為第一次遇到會不會覺得是壞掉了？
