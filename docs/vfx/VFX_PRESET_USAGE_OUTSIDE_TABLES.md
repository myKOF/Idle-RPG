# 不在配置表、但遊戲中有用到的 Preset

VFX Editor 的 Preset 下拉會在每個 id 後面標出「它被用在哪裡」，這樣挑 preset 時
一眼就看得出哪些已經上場、哪些還是孤兒。

用途來源有兩個：

1. **配置表**（自動掃描，不必維護）
   `config/CSV/Skills.csv`、`Skills2.csv`、`Status.csv` 的特效欄位。
   只要任一欄填了某個 preset id，就算那一列的技能／狀態有在用它。
2. **本檔**（人工維護）
   普攻、天罰、敵方出手這類**不屬於任何一列技能**的固定對應。它們沒有表格
   欄位可填，寫死在 `js/data.js` 的 `VFX_COMBAT_DEFAULTS`。

## 為什麼要人工維護一份清單

因為「程式碼裡出現這個字串」不等於「遊戲裡真的用到」，反過來也不成立：
Preset id 也可能出現在註解、測試、除錯開關裡。要判斷一個 preset 是不是孤兒，
需要的是**人**確認過的語意，不是 grep 的結果。

但人工清單會過期，所以有 `tests/vfx-preset-usage.test.cjs` 三面夾住：

- 本檔列的每一個 id 都必須真的存在於 `vfx/presets/`
- 本檔列的每一個 id 都必須真的還在 `js/` 裡被引用（刪掉功能卻忘了刪這一列 → 轉紅）
- `js/` 裡被引用、而配置表沒有的 preset，都必須列在本檔（新增寫死對應卻忘了登記 → 轉紅）

也就是說：**這份清單不會靜靜地過期**，它只會在你改動的當下轉紅一次。

`proj-ice-shard` 等）沒有列在這裡，因為它們**同時**也被配置表上的技能用到，
掃描配置表就找得到，不需要人工登記。

## 格式規定（測試會檢查）

- 表格只有三欄，順序固定：id、顯示標籤、用在哪裡。
- id 一律用反引號包起來，不加副檔名。
- 顯示標籤不得含有半形括號 `()`，也不得含逗號——它會被塞進
  `「<id>（<標籤>）」` 這個字串裡。

## 新增一筆的時機

在 `js/` 裡新增一個「寫死的 preset 對應」而且它沒有表格欄位可填的時候。
如果那個對應**應該**填在表上，正確的做法是去填表，不是登記到這裡——
本檔是給「結構上沒有欄位可填」的情況用的，不是給偷懶用的。
