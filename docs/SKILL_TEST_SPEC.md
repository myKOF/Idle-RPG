# 技能檢驗流程規範（SKILL TEST SPEC）

> 適用對象：所有被指派技能測試任務的 Agent（Claude／Codex／Antigravity）。
> 適用範圍：新版主動技能系統（`js/skills2.js`，8 群組 × 7 階）為主；
> 舊技能與潛力技能沿用同一流程（無階層者略過階層相關項目）。
> 測試完畢**必須**輸出報告（格式見 §7），存放於 `docs/skill-tests/`，供後續追蹤調教。
>
> **特殊群組（2026-08-14 第二批）**：
> - `counter`（反擊）＝**主動型被動**（新技能類型）：受擊觸發、永不主動施放，
>   但**必須裝配到技能列才生效**——B6 裝備/卸下照常驗，另加驗「未裝配時完全不觸發、
>   卸下後立即失效」；測試時必須讓敵人攻擊你（god 1 不影響觸發）；招架／破甲擊依賴格擋，
>   用 `statset block 100` 保證每次受擊都格擋；反擊傷害以**普攻組態**計算（statset atk 直接有效）。
>   V 類另加驗：戰鬥快捷列該格有**旋轉流動外框**且不顯示冷卻碼錶。
>   **法力（2026-08-19）**：每階觸發各自扣該階的施法消耗（T1 5／T2 10／T4 40／T5 60／T6 80／
>   T7 100；T3 不扣），付不起的那一階不觸發。因此測試前請確認法力充足（或刻意壓低法力驗證
>   「低魔時只剩便宜的階還在動」）；法力見底時快捷列該格會變成一般技能的**無魔**樣式。
> - `bloodrage`（嗜血狂怒）＝爆發增益：無直接傷害，N 類數值驗證改為量測持續期間的
>   攻速／爆傷／總傷／反震／連擊變化與擊殺延時；血飲術反噬請暫時 `god 0` 驗證實際扣血後再開回。

## 0. 測試環境準備（每次測試前依序執行）

測試一律在**本機測試服**進行（GM 指令只在 localhost 生效）。
以下 GM 指令可在遊戲畫面按 `Enter` 開啟 GM 輸入框執行，
或由 Agent 在瀏覽器 console 以 `WorkerBridge.send('gm.exec', { line: '<指令>' })` 執行。

| 步驟 | 指令 | 作用 |
|---|---|---|
| 1 | `god 1` | 鎖血：我方生命最低保留 1，不會死亡（測試環境必開） |
| 2 | `maxstats` | 測試基準組：攻速頂到上限、冷卻縮減頂到屬性上限、命中 999（消除 MISS 噪音） |
| 3 | `statset atk 100000` / `statset matk 100000` | 攻擊力固定為基準值 **100000**（物攻技能用 atk、魔法技能用 matk；跨存檔、跨測試輪可比較） |
| 4 | `statset crit 0` | 平衡測試時關閉爆擊消除方差；**爆擊相關技能測試時改設 `statset crit 100`** |
| 5 | `sglv <群組> <等級>` | 直設待測技能等級（不扣金幣；自動套用循序解鎖正規化） |
| 6 | `spawn <數量> [敵種] [血量倍率]` | 演武場出怪（見下）；期間自然出怪與過關結算暫停 |
| 7 | 測試結束：`spawn off`、`statset clear`、`god 0` | 恢復正常遊戲狀態 |

**法力與回魔規範（MP 常態保持不缺乏）**：
- **MP 回復需常態保持不缺乏情況**：在數值與平衡測試全流程中，法力必須常態維持充足，確保技能冷卻歸零時能立即施放，避免因法力不足導致技能延遲或停放，進而干擾技能冷卻、出手節奏與 DPS 輸出曲線量測。
- **提高回魔方式**：可透過裝備鑲嵌**回魔寶石（藍晶石 `kyanite`／`mpRegen`）**來大幅提高每秒法力恢復量（例如指令 `gem kyanite 10 10` 取得高等級藍晶石並鑲嵌至裝備插槽），使回魔速度遠大於技能法力消耗。
- 僅在 §2 N9「資源消耗」項目刻意驗證「MP 不足不施放」閘門時，才手動消耗或調低法力進行邊界測試。

`spawn` 說明：
- `spawn 8`＝8 隻小怪；`spawn 4 elite`＝4 隻菁英；`spawn 1 boss`＝1 隻 BOSS。
- 第三參數為血量倍率：**量測 DPS 一律用高倍率血木樁**，避免目標死亡干擾數據。
  倍率以「120 秒量測期內無敵人死亡」為準——低關卡搭配基準攻擊力時 1000 倍仍會被秒殺，
  請視情況拉高（上限 1000000）；實測有敵人死亡就提高倍率重測。
  功能驗證（屍爆、擊殺觸發類）才用低倍率讓敵人死得掉。
- 演武場敵人不計入過關配額，擊殺不推進關卡；`spawn off` 或重新整理即恢復。
- 上限 32 隻（可超過自然戰場的同時上限，供平衡測試用）。

**基準屬性組定義**（報告必須註明使用的基準組版本）：

| 基準組 | 內容 |
|---|---|
| `STD-202608` | god 1；maxstats（攻速上限／CDR 上限／命中 999）；atk=100000（魔法技能 matk=100000）；crit=0；**MP 回復常態保持不缺乏（可鑲回魔寶石 kyanite 提高回魔）**；裝載欄**只裝待測技能** |

其他會影響輸出的來源（裝備元素攻擊、傳奇特效、天賦、潛力技能）在平衡測試時應盡量歸零
（用低裝備存檔或卸裝測試）；無法歸零時必須在報告「環境備註」欄載明。

## 1. 基礎驗證（每個技能群組必測）

| # | 項目 | 通過標準 |
|---|---|---|
| B1 | 解鎖狀態 | 第 1 階預設開啟（Lv.1）；第 N 階在第 N−1 階達 Lv.1 前顯示鎖定且無法投資 |
| B2 | 升級 | 每階可由 Lv.0/1 逐級升至上限 10；等級、說明文字數值、面板徽章同步更新 |
| B3 | 金幣消耗 | 升級費用＝表定「基數 × 倍率^目前等級」（取整）；金幣不足時按鈕反灰且指令被拒 |
| B4 | 降級 | 可逐級降回；第 1 階最低 Lv.1；後續階已投資時前一階不可降到 Lv.0（有明確提示） |
| B5 | 進階組合 | 高階效果（如第 7 階）啟用時，低階效果仍正確疊加（例：傷害強化與本體累加） |
| B6 | 裝備/卸下 | 可裝入裝載欄與卸下；重複裝備被拒；裝載欄晶片顯示正確名稱與總等級 |
| B7 | 存檔往返 | 升級＋裝載後重新整理：等級、裝載狀態完整保留 |
| B8 | 指令邊界 | 跳階投資、未知群組、超上限等非法操作被拒且訊息正確 |

## 2. 數值驗證（每個技能群組必測；用 STD-202608 基準組）

以固定 atk=100000 為基準，逐項核對「表定公式值」與「實際傷害飄字／統計」：

| # | 項目 | 驗證方法 |
|---|---|---|
| N1 | 基礎傷害 | 單發傷害 ≈ atk × 表定%（防禦影響後仍應與理論值同量級；用 `spawn 1 small 1000` 單木樁量測） |
| N2 | 每級成長 | 抽驗 Lv.1／Lv.5／Lv.10 三檔，傷害成長符合「底值＋增量×等級」（Lv.1 已含 1 級升級效果，Lv.10＝底值＋增量×10） |
| N3 | 段數/次數 | 命中飄字段數＝表定 hits/次數；小數次數以機率觸發（多次施放統計頻率±10%內） |
| N4 | 目標數 | 受擊目標數＝表定值（spawn 足量敵人後逐發計數）；目標不足時的分配規則符合說明 |
| N5 | 彈射/連鎖數 | 彈射次數、連鎖上限、彈射傷害%符合表定（觀察飄字鏈與傷害比值） |
| N6 | 屬性加成 | 物理技能吃物攻不吃魔攻（statset atk/matk 對照）；元素附傷、敵種加成等照普攻同規格 |
| N7 | DoT | 每跳量＝技能傷害×dotPct%；作用間隔、持續時間、間隔縮短的總傷變化符合表定 |
| N8 | 冷卻 | 實際冷卻＝(基礎−固定縮減)×(1−CDR)，下限 GCD；爆擊縮冷卻類逐次生效 |
| N9 | 資源消耗 | 施放扣表定 MP；MP 不足不施放 |
| N10 | 機率類 | 機率觸發項（連刺、暈眩、感染…）以 ≥50 次樣本統計，頻率在表定值 ±10 個百分點內 |

數值不符時：先確認 `Skills2.xlsx` 表值與 `js/skills2.js` 一致（可能是套用參數未跑），
再回報為程式問題。

## 3. 特效驗證（每個技能群組必測）

**專屬特效原則：每個技能的特效都是專屬特效。**
除非該技能的設計說明特別載明允許共用，否則不得沿用通用原型預設畫法或其他技能的特效；
應為該技能新增專用的特效變體（`variant`，協議 v17 起顯示層自由擴充、不動協議）。
驗收時「看得出是哪個技能」是底線：兩個技能的畫面表現不可混淆。

| # | 項目 | 通過標準 |
|---|---|---|
| V1 | 施放特效 | 施放瞬間有该技能專屬的起手表現（斬光形狀/顏色/軌跡與其他技能可區分） |
| V2 | 飛行特效 | 投射類有專屬彈體與軌跡；飛行時間與距離成正比（遠目標較晚命中）；傷害數字與命中同步 |
| V3 | 命中特效 | 每次命中有受擊反饋（閃光/粒子/震動）；多段命中逐段呈現不擠成一團 |
| V4 | 持續性特效 | DoT 有可見的狀態標示與週期表現；領域/化身類全程可見且到期消失（無殘留節點） |
| V5 | 專屬性 | 與其他技能同屏施放時可明確分辨；未經允許不得出現「借用」的他技能特效 |
| V6 | 降載與清理 | 高負載下特效可降級但不影響結算；長時間戰鬥無特效殘留、無 console 錯誤 |
| V7 | 雙路徑 | Canvas（野外）與 DOM（高塔/`?canvas=0`）兩條路徑都有對應表現（允許 DOM 簡化但不可缺席） |

特效缺失或共用時：在報告標記 `V-FAIL`，註明「目前用的是哪個原型/誰的特效」，
由使用者決定是否開特效工程任務；**測試 Agent 不自行實作特效**。

## 4. 平衡驗證（DPS 曲線；用 STD-202608 基準組）

量測「同一技能在不同敵人密度下的 DPS」，供調教對照。

### 4.1 場景矩陣（每個技能群組跑完整組）

| 敵種 | 數量檔位 | 出怪指令 |
|---|---|---|
| 小怪 | 1、2、4、8、12、16、20 | `spawn <N> small 1000` |
| 菁英 | 1、2、4、6、8、10 | `spawn <N> elite 1000` |
| BOSS | 1、2 | `spawn <N> boss 1000` |

### 4.2 量測方法

1. 裝載欄**只裝待測技能**（新版技能裝 `sg:<群組id>`；普攻仍在，故以「技能自身傷害」為準）。
2. 待測等級檔位：**全 1（各階 Lv.1）**與**全滿（`sglv <群組> max`）**兩檔必測；調教中可加測中間檔。
3. `spawn` 出怪 → 開啟統計面板（📊）→ `WorkerBridge.send('stats.reset', {})` 歸零
   → 計時 **120 秒** → 讀統計面板該技能的累計傷害。
4. `DPS ＝ 該技能累計傷害 ÷ 120`；每檔位跑 1 輪即可（機率類技能建議 2 輪取平均）。
5. 換檔位前重新 `spawn`（重建滿血木樁），並再次 `stats.reset`。

### 4.3 判讀基線

- 群體技能的 DPS 應隨敵人數上升（至表定目標數封頂後趨平）；單體技能應大致持平。
- 曲線出現「多敵反而更低」「超過表定目標數仍線性上升」等異常形狀時，標記 `P-FAIL` 回報。
- 各技能間的相對強弱**不設通過標準**——數據如實記錄，強弱取捨由使用者調教決定。

## 5. 驗證環境注意事項

- 全程 `god 1`：我方不死（生命最低鎖 1）。護盾/受擊觸發類技能照常運作。
- **MP 常態保持充足**：測試全流程中 MP 需常態保持不缺乏（可鑲嵌藍晶石 `kyanite` 等回魔寶石），確保技能出手完全受限於表定 CD 與 GCD，消除缺魔對技能循環與輸出數據的干擾。
- `maxstats`＋`statset` 的覆寫**不入存檔**，重新整理即清除；測試後仍請執行 §0 步驟 7 還原。
- 演武場（`spawn`）期間關卡不推進、擊殺不計配額；但金幣/經驗照常獲得，屬可接受污染。
- 測試存檔請用**測試專用存檔**，不要拿正式遊玩存檔跑（GM 等級/金幣會污染進度）。
- 高塔相關技能行為（無座標退化）另以高塔實戰抽驗，不納入 DPS 矩陣。
- 發現任何 console Error 一律記錄（訊息＋重現步驟），無論是否影響測試進行。

## 6. 職責分工

- **數值/機制/平衡測試（§1、§2、§4）**：可由任一 Agent 以 GM 指令＋統計面板執行；
  結果數據不得手改，異常一律如實記錄。
- **特效/UI 目視驗證（§3）**：優先由 Antigravity 以瀏覽器實機執行。
- 測試 Agent **唯讀**：發現問題只回報，不修改程式；報告檔與 `docs/AI_TASKS.md` 除外。
