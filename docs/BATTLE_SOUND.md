# 戰鬥音效：普攻命中音（2026-11-05使用者核准）

| 音檔 | 說明 |
| --- | --- |
| assets/audio/hit-slash-a.wav | 斬擊A，約0.21秒，頻率一路降到低頻 |
| assets/audio/hit-slash-b.wav | 斬擊B，約0.31秒，中途回升的起伏 |
| assets/audio/hit-sword.wav | 劍擊，約1秒，金屬餘響 |

三個音皆為自製：tools/audio/hit-slash.cjs 以程式合成（噪音＋掃頻濾波＋金屬泛音），可重產，試聽檔在 audio/hit-preview。音色方向只參考 RPG Maker 的 Slash2／Slash10／Sword4 的聽感與頻譜走向，沒有使用任何取樣或波形（第二原則）。

## 行為
- 玩家主普攻（variant melee）命中時，從三個音隨機挑一個，不連續兩次同一個。一次主普攻只播一聲，不隨連擊段數或目標數增加。
- 音量：檔案本身已降30%，遊戲內再乘0.6（使用者要求比原本降低40%），設定在 js/sfx.js 的 SFX_FILES。
- 不是出手就播，而是在「劍砍到」那一幀：3D主角每個普攻動作有 hit 時間點，延遲＝hit的原速毫秒 ÷ 目前播放倍率（hero3d.js 的 hitDelayMs，攻速越快倍率越高、延遲越短）。沒有動作可對時間（例如施法動作佔著）就立刻播。
- 高攻速限流（js/sfx.js 的 SFX_GROUPS.basicHit）：兩次發聲至少間隔90ms；同時最多3個聲音在播。超過直接丟棄，不排隊補播。限流在真正要播的那一刻才判斷。背景分頁不播。

## 驗證重點
高攻速（每秒10下以上）時聲音是否黏成一團或爆音；砍到敵人的瞬間是否與音效同步；低攻速時延遲是否過長。

# 技能音效（2026-11-06 使用者核准並要求全部接入）

23 種玩家技能各有一個主音效（1～8 階共用），技能額外呼叫的特效（隕石、火龍吞噬、冰晶爆裂…）各有額外音效；大型物件分「飛行」與「砸地」兩段，持續型場域是循環音效。全部由 `js/sfx-synth.js` 以 Web Audio 程式合成，沒有任何外部錄音或音色庫。試聽與核准過程：第 1～3 輪試聽頁（使用者選定「烈焰翻騰」為火球、「柴火劈啪」為火龍捲循環、雷球 A 的「電弧劈啪」層為電流聲；風刃改為刀風雙層＋砍中木質共振）。

## 哪個技能播哪個音：Skills2 表的音效欄

Skills2 新增 11 個音效欄，與 11 個特效欄一一對應：

| 音效欄 | 對應特效欄 | 何時響 |
| --- | --- | --- |
| 施放音效 | （無） | 施法動作的硬直結束、技能放出去那一刻（act 事件，協議 v73） |
| 攻擊音效／觸發音效 | 攻擊特效／觸發特效 | 該事件的主要角色是攻擊本體時 |
| 飛行音效／觸發子彈音效 | 飛行子彈／觸發子彈 | 起飛時；飛行類音效長度自動對齊飛行時間 |
| 受擊音效／觸發命中音效 | 受擊特效／觸發命中特效 | 命中那一刻（飛行物在抵達時） |
| 地板音效／觸發地板音效 | 地板特效／觸發地板特效 | 場域出生時一次；循環音效則持續到場域消失 |
| 持續場域音效／觸發持續場域音效 | 持續場域特效／觸發持續場域特效 | 同上 |

- 填 `js/sfx-synth.js` 的 RECIPES 登記的 id（例：`fireball`、`meteor-fly`、`firepillar`）。打錯字或填在沒接線的觸發列，「套用參數.bat」會拒絕並說明哪一格、怎麼改。
- 解析規則與特效完全相同（`js/skills2.js` 的 `sgRoleTable`，`sgVfxRoles`／`sgSfxRoles` 共用）：本體欄留白沿前階繼承、超神空欄從第七階繼承；觸發欄只讀本列（是不是觸發事件看該列有沒有接線的 triggerVfx）。呼叫端直接指定特效角色表（vfxRoles）時，只留下那幾個角色的音效。
- 音效只在該角色真的播放時響：主要角色＋地板／持續場域，受擊在命中時刻。沒有填音效的事件不帶 `sfx`。
- **中毒／流血這類狀態每次作用時不發聲**（2026-11-08 使用者要求）：招式本身的施放、命中照常有聲；狀態每跳、以及每跳機率觸發的附帶效果不發聲——每拍觸發的萬毒血霧、中毒每跳機率觸發的毒霧感染、持續傷害每跳機率提前結算的零日感染，表上不填音效（崩解是狀態結束時炸一次，保留）。燃燒／中毒／流血等狀態每跳本來就沒有音效。循環音效（火龍捲、暴風雪…）不受影響。場域本身的定時作用不算狀態每跳：雷球每次放電、暴風屏障每次撕裂仍會響（音效設定 retrigger），其他地板／持續場域的單次音效只在出生時響。
- 敵人技能列不接音效（填了會被拒絕）。

## 三種音效

- **單次**（oneshot）：每個預先算 3 種隨機變化輪流播，不連續兩次同一個。
- **飛行**（flight）：長度＝這一則事件的飛行時間（以 0.05 秒為一格快取 24 種），第一次要先算，算好時已經晚了就從中段接著播，落地仍對齊。
- **循環**（loop）：算一段 4 秒、首尾交叉淡化的循環；以場域 id 為鍵，每次續命延長壽命，過期淡出。同一種最多 2 條、全部最多 6 條。`storm-barrier` 這類填在施放音效的循環播 `castSec` 秒。

## 限流與音量

- 每個音效獨立限流：`minGapMs`（預設 70ms，雙刀亂舞 450、嗜血狂怒 300、雷球 450、暴風撕裂 800）內只響一次、同時最多 `maxVoices`（預設 3）個；超過直接丟棄，不補播。
- 響度：各音效的 `gain` 依實測 RMS 校正到相近聽感，循環音效刻意壓低；整體再乘 `SYNTH_VOLUME`（0.8）與設置→音訊的音效音量，並受「我方攻擊音效」開關控制。多個技能同時響時有一道 -6dB 的保護壓縮。
- 背景分頁不播、循環音效立刻淡出。

## 驗證重點

- 各技能的主音效是否在畫面對應的那一刻響（命中、爆炸、龍捲出現與消失）。
- 高攻速／多目標時是否黏成一團或爆音（嗜血狂怒、雙刀亂舞、雷球、連鎖閃電）。
- 循環音效是否在場域消失後停止（火龍捲、水龍捲、暴風雪、雷幕、飛雷神、虛空圓盤）。
- 隕石／雷隕天落的飛行聲是否在砸地那一刻接上砸地聲。
