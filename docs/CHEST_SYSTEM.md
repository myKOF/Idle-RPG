# 熔爐寶箱（2026-11-12）

熔爐頁上方的置頂寶箱列。拆解裝備累積各寶箱的**鍛造經驗**，滿額得到 1 個寶箱；寶箱可用金幣升級，等級越高掉落越好。

## 規則

- 五種品質：普通（青銅寶箱）、稀有（精良寶箱）、史詩（史詩寶箱）、傳說（傳說寶箱）、神話（神話寶箱）。
- 開局只解鎖「初始解鎖＝是」的寶箱（預設青銅）。其餘寶箱在**第一次得到該寶箱的鍛造經驗**時解鎖；未解鎖前置灰並以鎖鏈與掛鎖鎖住，下方提示「拆解 X 以上裝備解鎖」（X＝表上第一個拆解經驗大於 0 的品質）。
- 任何拆解都算：熔爐入爐、背包手動拆解、背包滿載自動拆解、GM 拆解、離線熔爐補算；離線期間熔爐佇列已滿而折算碎片的裝備也視同已拆解。全部經過 `factory.js doSalvage` → `chestGainSalvageXp(品質)`（離線折算在 `save.js`）。
- 經驗依寶箱**目前等級那一列**的「拆解經驗R0～R11」累加；每滿「寶箱鍛造經驗」得 1 個。每種最多 9999 個，存滿後經驗停在滿格，開掉一個後下一次拆解立刻補上。
- 升級：從目前等級升一級需 `a ＋ b^目前等級` 金幣，費用無條件進位。每種寶箱的上限取 Chest 表該編號的最後一級，各種寶箱可以有不同上限。
- 開啟：每開 1 個擲「開啟掉落數」輪（可寫 `a~b` 每個寶箱隨機輪數）；**每一輪裡每個掉落格各自獨立擲骰**，格上的數字就是該格每輪的掉落機率（%），格與格互不排擠，一輪也可能什麼都沒掉（獎勵為空仍扣 1 個寶箱）。「開啟」開 1 個、「全開」一次開完持有數，熔爐紀錄會寫一行。
- 獎勵在置中的無框全畫面彈窗顯示，沿用離線收益的黑色遮罩及標準確認按鈕。依遺物、符文、金幣等資源、寶石、裝備排列，遺物沿用遺物頁的圓形圖示並填滿格位。裝備由高品質到低品質逐件顯示背包同尺寸圖示、等級及太古星數，格位無提示。首屏圖示由左到右逐列出現，約兩秒內完成。可拖曳、滾輪或觸控滑動瀏覽，捲軸隱藏，按「確定」或 Esc 關閉。
- 裝備和野外掉落一樣送進熔爐佇列（依各熔爐品質勾選拆解或保留入包）；佇列滿改放背包，背包也滿就直接拆解（產出照給），不會遺失。
- 離線結算結束時，戰鬥日誌列出「離線期間寶箱累積」，離線摘要資料帶 `sum.chests`。

## 配置表 config/Excel/Chest.xlsx

一列＝一種寶箱的一個等級；欄位說明也寫在 Excel 的「欄位說明」頁。改完儲存並關閉 Excel，執行「套用參數.bat」：
`Chest.xlsx → config/CSV/Chest.csv → tools/config_tables.cjs（SCHEMAS.Chest）→ js/chest_data.js 的 CHESTS`。表格有錯時整次中止並指出列與欄。

| 欄位 | 說明 |
|---|---|
| 編號 | 寶箱編號，介面依編號由左到右排列 |
| 寶箱名稱／寶箱品質／初始解鎖／升級金幣a／升級金幣b | 整種寶箱共用：第 1 級必填，之後留白＝沿用，填了必須相同。品質填 普通／稀有／史詩／傳說／神話 |
| 等級 | 同一編號從 1 連續填到要開放的最高級，例如填到 100 就能升到 Lv.100 |
| 寶箱鍛造經驗 | 得 1 個寶箱所需經驗；留白＝沿用上一級 |
| 拆解經驗R0～R11 | 拆解一件該品質裝備得到的經驗；0＝不給；留白＝沿用上一級 |
| 開啟掉落數 | 每開 1 個擲幾輪：整數（1～100）＝固定輪數，`a~b`＝每個寶箱在範圍內隨機輪數；留白＝沿用上一級 |
| 掉落1～掉落16 | 每格一個候選，寫法見下；16 格全留白＝沿用上一級整組掉落 |

### 掉落格寫法

`項目[:參數[:參數2]][*數量]=機率`。`=` 後面是**該格每一輪的獨立掉落機率**（%，大於 0、至多 100）：不是權重、不必加總為 100，每個格自己擲一次骰（`金幣*2000~6000=30` ＝ 每輪 30% 掉 2000~6000 金幣）。數量與參數可寫 `a~b`（含頭尾，均勻隨機）；數量符號寫 `*`（`×`、`x` 也收），省略＝1 個。遺物格的機率會被「幸運符」放大（放大後上限 100%）。

| 項目 | 參數 | 例 |
|---|---|---|
| 金幣、裝備碎片、附魔精華、太古精華、神性之石、魔魂本源、邀請券（神祕商人邀請券）、技能經驗、經驗（角色經驗） | 不帶 | `金幣*1000~5000=30` |
| 寶石 | 階級 1～10（種類從開放中的寶石隨機） | `寶石:3~5*1~2=12` |
| 符文 | 階級 1～符文總數 | `符文:7~9=8` |
| 裝備 | 品質 0～11 或名稱；參數2＝太古條數（省略＝自然擲骰）。等級依目前關卡 | `裝備:傳說:2=3` |
| 遺物 | 省略＝隨機一件；填編號＝指定 | `遺物=1`、`遺物:30=0.5` |

## 程式

| 檔案 | 內容 |
|---|---|
| `js/chest_data.js` | `CHESTS`（配置表產生，兩端共載） |
| `js/chest.js` | 兩端共載。純函式：`chestEntry`、`chestUpgradeCost`、`chestDropOdds`、`chestRewardLabel`；Worker：`chestGainSalvageXp`、`chestOpen`、`chestUpgrade`、`chestPanelView`、`sanitizeChests` |
| `js/ui-chest.js`、`css/chest.css` | 置頂寶箱列（主執行緒）：透明 WebP 寶箱圖、經驗條、開啟／全開／升級、掉落機率提示、全畫面獎勵彈窗 |
| `images/chests/` | 五款寶箱圖。母圖與提示詞收錄於 Effects-Materials 的 `codex-authored/forge-chests-20261112`，以 `node tools/assets/export-chest-art.cjs --apply` 匯出。 |

- 存檔：`G.player.chests = { 編號: { lv, xp, n, on } }`，新局為空物件，缺項依表格預設補上；`migrateSave` 呼叫 `sanitizeChests`。表上暫時拿掉的編號原樣保留。
- 協議 v81：`chest.open({chestId, count})` 的裝備獎勵附圖檔路徑、實際等級、太古星數與件數。`chest.upgrade({chestId})` 與 `newforge.chests` 面板投影維持原契約。
- GM：`chest 編號|all [數量]`、`chest lv 編號|all 等級`、`chest reset`（見 GM_command.md）。
- 測試：`tests/chest.test.cjs`。

## 預設數值

初始表由 AI 依「品質越高起點越高、每級金幣／材料約 ×1.2～1.3、寶石／符文／裝備品質每 4～7 級進一階、每 5 級多擲 1 輪」排出，供企劃再調整；實際數字以 Chest.xlsx 為準。
