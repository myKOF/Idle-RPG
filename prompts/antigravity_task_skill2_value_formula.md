## 1. 這次改了什麼（驗證前先讀）

新版技能系統（`SKILLS2`，17 群組 × 7 階）的每階效果值算法改了一行：

| | 舊 | 新 |
|---|---|---|
| 算式 | 底值 + 增量 ×（等級 − 1） | **底值 + 增量 × 等級** |
| Lv.1 | ＝底值 | ＝底值 + 增量 × 1 |
| Lv.10 | ＝底值 + 增量 × 9 | ＝底值 + 增量 × 10 |

以連鎖閃電第 1 階（設計文檔：效果 150%、升級效果每級 +15%）為例：

| 等級 | 舊 | 新 |
|---|---|---|
| Lv.1 | 150% | **165%** |
| Lv.2 | 165% | 180% |
| Lv.10 | 285% | **300%** |

**設計意圖**：設計文檔的「效果」欄是**不含任何升級效果的底值**，技能 1 級時就已經吃到
1 級升級效果，練滿 10 級剛好等於文檔的滿級值。舊實作少給了一級，所以滿級永遠差一格。

**參數表一個數字都沒動。** `config/CSV/Skills2.csv` 與 `Skills2.xlsx` 完全沒改，
改的只有引擎讀表的方式（`js/skills2.js` 的 `sgVal()`）。

### 為什麼「顯示」和「計算」可以一起驗

`sgVal()` 是整個新版技能系統**唯一**的取值收斂點：技能面板的說明文字（`describeSkill2Tier`）
與戰鬥結算走的是同一支函式。因此：

- 「面板寫 165%、實際打出 150%」這種矛盾**理論上不可能**——除非主執行緒與 Worker
  載入到不同版本的 `js/skills2.js`（見 §4，這是本次真正的風險點）。
- 所以你的重點不是「面板 vs 傷害」互相對照，而是**兩者一起對照設計文檔**。

### 會影響手感的副作用（不是 bug，但要確認可接受）

「追加次數／目標數」類參數（表上的 `add`）在 **Lv.1 就帶小數**了。
例如雷鳴術 `add: 1, addPer: 0.1` → Lv.1 ＝ 1.1 次，整數 1 次保底、**0.1 的部分以機率觸發**。

舊版 Lv.1 剛好是整數 1，段數是確定的；現在從 Lv.1 起就有隨機性。
受影響的階至少有：迴旋斬【強化斬】、飛刀【強化彈射】、疾風斬【疾風連斬】、
雙刀亂舞【疾風亂舞】、嗜血狂怒【狂化連殺】、泥沼術【毒沼增生】、
連鎖閃電【雷鳴術】【強化連鎖】【雷電暴風】、落雷術【落雷連鎖】【雙重落雷】、雷球【多重雷球】。

## 2. 主線驗證：顯示值 vs 設計文檔（A 類）

**這是本任務的核心。** 對照基準是**設計文檔「技能」頁籤**（線上試算表），
每一階有「效果」欄與「升級效果」欄。判定規則只有一條：

```
遊戲內 Lv.N 顯示值  ==  設計文檔「效果」欄  +  「升級效果」每級量 × N
```

因此 **Lv.10 的顯示值必須剛好等於設計文檔的滿級值**（多半是 300%、50%、40%、100%
這類整數；若你算出 285%、47.5%、38% 這種尾數，代表算式又退回舊版了）。

### A0：先把 119 階的顯示文字一次撈出來

console 執行下列片段，會印出 17 群組 × 7 階在 Lv.1／Lv.5／Lv.10 的完整說明文字。
**把輸出整份貼進報告**，之後每一條抽驗都引用它，不必反覆截圖。

```js
(() => {
  const rows = [];
  for (const gid in SKILLS2) {
    const g = SKILLS2[gid];
    g.tiers.forEach((t, i) => {
      [1, 5, 10].forEach(lv => rows.push({
        群組: g.name, 階: i + 1, 階名: t.name, 等級: lv,
        說明: describeSkill2Tier(gid, i, lv)
      }));
    });
  }
  console.table(rows);
  copy(rows.map(r => [r.群組, 'T' + r.階, r.階名, 'Lv.' + r.等級, r.說明].join(' | ')).join('\n'));
  console.log('已複製 ' + rows.length + ' 行到剪貼簿');
})()
```

### A1：滿級值對照設計文檔（**必做，全 17 群組**）

| # | 項目 | 通過標準 |

| A1 | Lv.10 滿級值 | 每一階顯示的每一個數字，都等於設計文檔「效果 + 升級效果×10」 |
| A2 | Lv.1 起始值 | 每一階都等於「效果 + 升級效果×1」，**不等於**設計文檔「效果」欄的裸值 |
| A3 | 每級增量 | Lv.5 − Lv.1 ＝ 升級效果 × 4；Lv.10 − Lv.5 ＝ 升級效果 × 5（線性、無跳格） |
| A4 | 無升級效果的欄位 | 設計文檔「升級效果」欄留白的參數（次數、角度、米數等定值），**Lv.1 到 Lv.10 完全不變** |

有兩個階的升級效果是**負的**（升級＝數字變小）：

| 群組·階 | 效果 | 通過標準 |
|---|---|---|
| 火球術【強化燃燒】 | 燃燒作用間隔縮短 | Lv.1 應小於文檔的底值、Lv.10 為文檔滿級值；**任何等級都不得 ≤ 0 或出現負數** |
| 大地守護【天地共生】 | 自身冷卻秒數遞減 | 同上；Lv.10 的冷卻仍需 > 0，且技能格倒數顯示正確 |

### A6：面板「下一級」預覽

| # | 通過標準 |

## 3. 實際結算對得上顯示（B 類）

顯示對了不代表打出來對。用木樁量測，**每條都要有實測數字**。

布場（console：`WorkerBridge.send('gm.exec', { line: '<指令>' })`，或遊戲內 `Enter` 開 GM 框）：

```text
level 1000                  拉到所有解鎖門檻之上（雷球第 7 階需 700 級）
gold 1e15                   升級技能用
maxstats                    攻速／CDR 上限、命中 999
statset atk 100000          物理群組的基準攻擊力
statset matk 100000         魔法群組的基準攻擊力
```

技能等級：`sglv all 1`（全部只投第 1 級）與 `sglv all max`（全滿）兩檔各跑一輪。

裝配（**一次只裝一個測**，多個技能的飄字疊在一起分不出誰是誰）：
