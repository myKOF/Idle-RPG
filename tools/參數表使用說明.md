# 參數表使用說明（Excel → CSV → 遊戲）

## 檔案位置

| 檔案 | 路徑 | 角色 |
|---|---|---|
| **Excel 主檔** | `config/Excel/game_parameters.xlsx` | 你平常編輯的地方（工作表：`game_parameters`） |
| CSV（自動產生） | `config/CSV/game_parameters.csv` | 由 xlsx 轉出、系統實際讀取；**每次套用會被覆蓋，不用手改** |

## 怎麼調整遊戲數值（雙擊一次就好）

1. 用 **Excel 打開 `config/Excel/game_parameters.xlsx`**，在 `game_parameters` 工作表改「參數a、參數b、…」欄裡的**數字**（或元組裡的數字）。
2. **存檔（Ctrl+S）**。此時遊戲**不會**刷新。（Excel 可以繼續開著，不必關。）
3. **雙擊專案根目錄的「套用參數.bat」**。它會依序：
   - **[1/3]** 撥離七表（技能/狀態/寶石/天賦/裝備詞條/NPC/任務）：把 `Skills/Status/Gems/Talents/Equipment_Affix/NPC/Task.xlsx` 轉成同名 CSV，再寫回 `js/skills.js`／`js/status.js`／`js/data.js`（見下方「撥離七表」）。
   - **[2/3]** 把 `config/Excel/game_parameters.xlsx` 轉成 `config/CSV/game_parameters.csv`（直接讀 xlsx 位元組，Excel 開著也能轉）。
   - **[3/3]** 把 CSV 數值寫進 `js/data.js` / `js/formula.js`（含安全檢查：備份、語法檢查、失敗自動還原）。
   - 成功後視窗自動關閉；失敗會停下來顯示原因。
4. **開著的遊戲（本機）約 2 秒內會自動重新整理**，新數值立即生效——不用按任何按鈕、不用手動 F5。

> 原理：套用成功時會更新根目錄 `params_version.txt`；遊戲內的 `js/param_autoreload.js`（只在本機運作）
> 每 2 秒讀一次該檔，內容一變就自動重載。外部玩家沒有這支輪詢，也不受影響。

### 為什麼存檔不會刷新、套用才刷新？

`.vscode/settings.json` 已把整個 `config/` 資料夾（xlsx、csv）排除在 Live Server 監看之外，所以存檔不觸發重整；
只有雙擊 `.bat` 更新了 `params_version.txt`，才由遊戲內的輪詢器重整「一次」。
（改過 `.vscode/settings.json` 後，Live Server 需**停止再重新啟動**才會生效。）

### 熟悉終端機者也可打指令

```
node tools/xlsx_to_csv.cjs             # 只做 xlsx -> csv（不套用）
node tools/apply_params.cjs            # 試跑，只列出將變更，不改程式
node tools/apply_params.cjs --write    # 實際寫回（一樣會觸發自動重載）
```

## 欄位說明（哪些欄有作用）

工具**以表頭名稱定位欄位**（找 `系統分類`／`名稱`／`參數a`），不是靠欄位位置。所以：

- **`編號`、`變動` 欄只是給你看的註記,工具完全忽略**。`變動` 欄用來標記每列狀態,供 AI 判斷是否改遊戲程式（不影響 `apply_params` 套用數值）:
  - **空白 / `0`**（Excel 常把空白填成 `0`）= 原有公式,維持不動。
  - **`新增`** = 本次新增的公式;當作個人測試,AI 不會主動接進系統,等你明確說要實作。
  - **`調整`** = 你要求修改「現有公式」（擴增參數或改結構）;把具體改法寫在該列「參數化公式」與「中文說明」,AI 會據此改遊戲程式。
- 你可以**在中間插入新欄、重排欄位**,只要表頭仍有 `系統分類`／`名稱`／`參數a` 這三個名稱,就不會錯位。
- 真正對應到程式的「鑰匙」是 **`系統分類` + `名稱`** 這個組合——這兩欄的文字**不要改**,且同分類下名稱不要重複。

## ⚠️ 在 Excel 裡調數值的注意事項

改用 xlsx 當來源後，過去「Excel 存 CSV 竄改冒號 / 科學記號」的問題**已不存在**（值直接存在 xlsx 裡）。
但仍請注意：

1. **不要把格子設成「百分比」格式。** 本表的百分比是用**整數**表示（例如 25 代表 25%）。
   若把格子設成百分比再輸入 `25%`，Excel 會存成 `0.25`，套用後數值就錯了。請保持「通用/文字」格式，直接填數字。
2. **元組 / 配對格**（例如 `{1~49=25}`、`5=50`）是**文字**，照原樣打即可，別讓 Excel 自動把它當公式或日期。
   若某格開頭是 `=`、`+`、`-`、`@`，Excel 會當公式；此類格請設成「文字」格式再輸入。
3. **套用前記得先在 Excel 按存檔**：轉換讀的是「已存到硬碟」的內容，未存的編輯不算數。
4. **尾端多出來的 `0` 不用管**：Excel 常把留空的參數格自動填成 `0`。單值列本來就只讀前面幾格、不看尾端;成對/元組表（寶石商店、掉落表）工具會自動略過這些補位 `0`,不會出錯。

## 安全機制

- **試跑優先**：`apply_params.cjs` 不加 `--write` 只會列印將變更清單，不動任何檔案。
- **寫入前備份、寫入後語法檢查**：`--write` 先在記憶體備份，寫入後用 `node --check` 驗證；寫壞會**自動還原**。
- **不猜**：某參數若在程式中找不到唯一位置，工具會標為「錨點問題」並**中止寫入**。
- **恆等保證**：沒改任何值時執行，一定回報「將變更 0」。
- **轉換忠實**：`xlsx_to_csv.cjs` 產出的 CSV 與原本手工維護的格式完全一致（UTF-8 BOM、CRLF、RFC-4180 引號）。

### 各表欄位

- **Skills**：`id`、`系統分類`(phys/magic/def/special/passive)、`名稱`、`icon圖號`(emoji)、`施法消耗`、`冷卻`、`施放AI`、`說明文字`、`基礎fx(JSON)`、`里程碑fx(JSON)`。
  技能效果結構複雜、每技能不同，故以 **JSON 字串**完整呈現；直接改 JSON 裡的數字即可（例如 `"base":360`）。
- **Status**（2026-08-11 技能及狀態改造）：`狀態ID`、`狀態名稱`、`狀態圖標`、`狀態分類`(buff/debuff/ctrl)、`狀態效果`(dot持續傷害／hot持續回復／stat屬性增減／ctrl行動限制／shield吸收護盾)、`效果鍵值`、`傷害屬性`、`傷害來源`(skill占技能傷害%／maxHp占目標最大生命%／value直接數值)、`狀態傷害`、`傷害上限參照`＋`傷害上限倍率`、`效果數值`、`持續時間`、`作用間隔時間`、`疊加規則`、`最大疊層`、`說明`。
  技能在 Skills 表的 `基礎fx(JSON)` 以 `"status":[{"id":"burn"}]` 引用狀態，可加 `dmg`／`dur`／`val` 覆寫本表預設值（保留各技能與里程碑的成長曲線）。
  **`Status.xlsx` 第二頁「欄位定義」**：完整欄位說明與新增狀態注意事項。作用間隔只改變跳傷節奏、不改變總量（到期會補跳餘額）。
  護盾（`shield`）是有持續時間的狀態：被打完或時間到就消失，秒數改 `shield` 那一列的「持續時間」即可。
  疊層：把任一列的「疊加規則」改成 `stack`、「最大疊層」填 2 以上就會生效（單層值取高、層數累加，效果值＝單層值×層數），不必改程式。
- **Gems**：`id`、`名稱`、`icon圖號`、`屬性桶`(stat)、`屬性名稱`、`基礎值`、`百分比`(TRUE/FALSE)、`線性`(TRUE/空)。
- **Talents**：`類型`(轉生天賦/潛力天賦)、`轉數`(1~10)、`id`、`名稱`、`icon圖號`、`屬性桶`、`低階值`、`高階值`、`每級值`(潛力用)、`解鎖數`、`停用`、`停用原因`、`說明`。
- **Equipment_Affix**：`池`(詞條池/傳奇特效/神鑄特效)、`id`、`名稱`、`基礎值`(詞條最基本值，不受品質／等級／太古影響)、`成長基礎值`(等級成長項的基準)、`每級成長`、`百分比`、`權重`(掉落出現權重)、`戰力權重`(戰力評分 `SCORE_WEIGHTS`；空白＝以 1 計)、`最低稀有度`、`出現部位`(部位以 `;` 分隔，空=全部)、`每階perR`、`屬性桶stats`(以 `;` 分隔)、`說明`、`效果類型`、`關聯技能`、`觸發技能`、`限定武器類型`、`效果參數JSON`。`限定武器類型` 可用 `;` 分隔多種武器；有填值的特效只會在指定武器上生成。`觸發技能` 即使尚未解鎖，也會以至少 Lv.1 免費觸發。
- **NPC**：`NPC識別碼`、`NPC名稱`、`所屬地圖識別碼`、`屬性`、`外觀`、`魔法型（1是／0否）`、`出現權重`。外觀欄沿用現有表格語意：一般地圖填 emoji；有獨立外觀 key 的 NPC 填 appearance key。NPC 的 `hpMult`／`atkMult`／`defMult`／`aspdMult` 等戰鬥倍率不在表內，套用時會保留 `js/data.js` 原值。
- **Task**（2026-08-05 主線任務）：`順序`(1 起、玩家循序領取)、`任務說明`(遊戲內顯示文字)、`目標類型`、`目標參數`、`目標數量`、`獎勵類型`、`獎勵參數`、`獎勵數量`、`獎勵顯示`(遊戲內顯示的獎勵文字)、`備註`(純說明欄，不寫回 JS)。
  - 目標類型：`equipSlots` 身上部位數（參數=`最低品質|最低等級`，品質為 RARITIES 索引：0普通/2稀有/3獨特/4史詩/5傳說；雙手武器視同佔用主副手）、`upgradeCount`/`rerollCount`/`enchantCount`/`composeCount` 累計次數、`socketCount` 身上目前鑲嵌寶石數、`forgeParts` 熔爐目前已裝配零件數、`forgePartLevel` 任一熔爐零件達 N 級（零件等級是全域的，卸下不影響）、`ancientCount` 身上太古詞條數、`maxHp` 生命最大值、`stageClear` 通關指定地圖第 N 關（參數=地圖識別碼，如 `desert`；可指定該地圖最後一關）、`towerFloor` 高塔已通關最高層、`skillLevel` 技能達 N 級（參數=技能 id，1=學會）。
  - 獎勵類型：`gold`/`scrap`/`essence`/`skillXp`（技能熟練度經驗）、`gem`（參數=寶石等級，種類隨機）、`book`（參數=附魔書 id，如 `focus`）、`equip`（參數=`品質|等級|太古數`；等級 0=依當前關卡、太古留空=自然擲骰）。
  - `獎勵顯示` 是玩家看到的文字，改獎勵數值時記得同步改它。
  - **`Task.xlsx` 第二頁「參數定義」**：完整的欄位與參數說明（目標／獎勵類型清單、品質索引、地圖識別碼、附魔書 id 對照、新增任務注意事項）。與 Skills 表的「變量定義」同性質——程式不讀取，同步流程只讀第一頁。

### 注意事項

- **鑰匙欄不要改**：Skills/Gems 的 `id`、Status 的 `狀態ID`、Talents 的 `類型+轉數+id`、Equipment_Affix 的 `池+id`、Task 的 `順序`——改了會被當成新項目。
- **布林值**填 `TRUE`／`FALSE`（或留空＝否）。
- **JSON 欄**（技能 fx、傳奇特效的效果參數）必須是合法 JSON：鍵與字串用雙引號，不要留多餘逗號。工具會在套用時解析並回報錯誤。
- 安全機制與主參數表相同：**寫回 JS 前備份、寫入後 `node --check`、失敗自動全數還原**；沒改任何值執行會回報「語意變更 0、未寫檔」。
- 若要重新由目前 JS 產生七表（重建 xlsx/CSV）：`node tools/config_tables.cjs --gen`。
  ⚠️ Task 表的「備註」欄是純說明欄、不存在 JS 裡，`--gen` 重建會清空該欄——Task 表請盡量直接編輯 xlsx。

## 進階
